# Plan: Prevent Expo Dev-Client Native Module Linking Issues

## Context Summary — What Happened

### Problem
After building a dev-client APK for Android, the app crashed with:
```
W ReactNativeJS: No native ExponentConstants module found
E ReactNativeJS: [runtime not ready]: Error: Cannot find native module 'ExpoAsset'
E ReactNativeJS: Invariant Violation: "main" has not been registered
```
This happened ONLY when the dev-client loaded the JS bundle from Metro (not on app startup).

### Root Cause
`expo-asset` and `expo-constants` were **nested dependencies** inside `expo/node_modules/` rather than top-level in `node_modules/`. The Expo build system generates `ExpoModulesPackageList.java` at build time — this file lists ALL native modules to register. Because `expo-asset` and `expo-constants` were nested, the autolinking plugin **didn't discover them**, so they were absent from the generated package list.

**Before fix** (`ExpoModulesPackageList.java`):
- Only had: ReactAdapterPackage, BasePackage, DevLauncherPackage, DevMenuPackage
- **Missing**: AssetModule, ConstantsModule

**After fix**:
- Added: ConstantsPackage, AssetModule, ConstantsModule

### What Fixed It
```bash
npx expo install expo-asset expo-constants
```
This promoted them from nested (`expo/node_modules/expo-asset`) to top-level (`node_modules/expo-asset`), making them visible to the autolinking scanner.

### Additional Issues Found & Fixed Along the Way
1. **`withNotificationListener` plugin** — Was using `modifyingApplicationManifest` which overwrote all `<application>` attributes, breaking autolinking entirely. Temporarily disabled (`plugins: []` in app.json).
2. **`newArchEnabled=true`** — Expo SDK 53 defaults to new architecture. The C++ autolinking (`autolinking.cpp`) was completely empty (all providers returned `nullptr`). Set to `false` in `gradle.properties` as a safety measure, though the real fix was the top-level install.
3. **Prebuild regenerates `newArchEnabled=true`** every time — must be changed AFTER each `expo prebuild --clean`.

## Preventive Measures — Test Plan

### 1. Post-Build Smoke Test (Automated)
Create a script `scripts/smoke-test-apk.sh` that verifies the generated `ExpoModulesPackageList.java` contains required modules:

```bash
#!/bin/bash
# After prebuild + build, verify critical native modules are in the package list
PACKAGE_LIST="node_modules/expo/android/build/generated/expo/src/main/java/expo/modules/ExpoModulesPackageList.java"

REQUIRED_MODULES=("AssetModule" "ConstantsModule" "ExpoFetchModule")

for module in "${REQUIRED_MODULES[@]}"; do
  if ! grep -q "$module" "$PACKAGE_LIST"; then
    echo "FAIL: $module not found in ExpoModulesPackageList.java"
    exit 1
  fi
done
echo "OK: All required modules found in package list"
```

### 2. Integration Test: Dev-Client Bundle Load
After installing APK on device, run via adb:
```bash
adb logcat -c
adb shell am start -n com.misgastos.app/.MainActivity
sleep 10
adb logcat -d -s ReactNativeJS:V | grep -c "Cannot find native module"
# Expected: 0
```

### 3. package.json Dependency Audit
Add to `expo-doctor` or a custom check:
```bash
# Ensure expo-asset and expo-constants are top-level, not just nested
node -e "
  const pkg = require('./package.json');
  const deps = {...pkg.dependencies, ...pkg.devDependencies};
  const required = ['expo-asset', 'expo-constants', 'expo-file-system'];
  for (const r of required) {
    if (!deps[r]) {
      console.error('MISSING top-level dep: ' + r);
      process.exit(1);
    }
  }
"
```

### 4. Gradle Properties Guard
After each `expo prebuild`, verify `newArchEnabled`:
```bash
grep "newArchEnabled=false" android/gradle.properties || echo "WARN: newArchEnabled is not false"
```

### 5. Pre-Commit Hook (Optional)
Check that `android/` is in `.gitignore` (since it's regenerated by prebuild) and that `expo-asset`/`expo-constants` are in `package.json`.

## Key Files Reference
- `mobile/node_modules/expo/android/build/generated/expo/src/main/java/expo/modules/ExpoModulesPackageList.java` — Generated native module registry
- `mobile/android/gradle.properties` — Contains `newArchEnabled`, `hermesEnabled`
- `mobile/app.json` — Plugins list (must not include broken config plugins)
- `mobile/package.json` — Must have `expo-asset` and `expo-constants` as top-level deps
- `mobile/plugins/withNotificationListener.js` — Disabled; needs rewrite to use `modifyingMainApplicationManifest` instead of `modifyingApplicationManifest`
